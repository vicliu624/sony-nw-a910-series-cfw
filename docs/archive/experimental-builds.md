# Experimental wording override builds

Two 1.03 candidates generated by `scripts/build-language-firmware.py`:

- English: SHA256 `a2ab1c788473dab63b4890bd86fb067189ccf4c0aa6ecdd4da2d26ec4273b891`.
- Simplified Chinese: SHA256 `debfa5166ccbc2ec5de33295d2ade25447dc982686d21ffaf5899de0e539a1c9`.

## Code evidence

At ARM VA 0x96114, code loads eleven wording files from pointer table VA 0x5417b8, hashing each filename with multiplier 37 and loading its DPK resource. At VA 0x96210, wording IDs up to 825 select a language-specific resource. VA 0x96294 loads the configured locale (`ldr r3,[r0,#0x14]`); after a bounds check at 0x96298, VA 0x962a8 selects the previously loaded resource pointer by that index.

Each candidate replaces only that one instruction with `mov r3,#0` (English) or `mov r3,#6` (Simplified Chinese). It does not rewrite resources, change instruction size, change control flow, or change the persistent device locale. Main ELF file offset is 0x8e294, original bytes `14 30 90 e5`.

## Offline verification

The original decompressed tar archive is modified directly at this member's data offset. Archive headers, file sizes, permissions, links and all other tar bytes are retained. Exactly three bytes differ in the entire decompressed rootfs tar. The rootfs gzip is recompressed; original UPG components 0, 1 and 2 remain byte-identical. UPG header file length and MD5 are regenerated. Both final artifacts are decrypted again and their gzip/tar contents verified against the intended patch. ARM instruction encoding independently decoded with Capstone.

These checks validate construction, not execution on the hardware. Chinese glyph coverage and model-specific page behavior remain untested. Loader screens and date formatting remain governed by the original device settings.
