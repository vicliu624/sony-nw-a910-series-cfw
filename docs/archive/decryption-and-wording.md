## Round-trip validation

Rockbox `upgtool --no-color -c -k b8442c44 -s 5dfeff3c` repacked all four extracted components. Repacked and original UPG SHA256 are both:

`cfbcc372e2a18f11c12a080c9e5f039333e09175f5db03ac841a4227d3896b32`

The independent Python extraction script also checks byte-identical decrypt/encrypt round-trip. This proves we can reproduce the outer UPG format. It does not prove that a device will accept modified application/resource contents or that they will render correctly.

## Actual UI evidence

- Main application: `usr/local/bin/gemini-ICX1101`, 5,691,632 bytes, ARM Linux ELF.
- Wording: `usr/local/share/gemini/res/wording_res/ICX-COMMON_wording.dpk`, 248,000 bytes.
- Font packs: `font/dui_font.dpk` and `font/ICX1101_dui_font.dpk`.
- Application string references include `DuiPageSID137_LS_SET_LANGUAGE`, its C++ source filename, `APCSettingLanguage`, and `ICX-COMMON_Wording_0.dwr` through `_10.dwr`, plus `_co.dwr`.
- Wording DPK has 12 indexed sections. Observed header and all increasing offsets are consistent with 16-byte header plus 12 16-byte index records.
- Section 1 at 0x440 is 22,800 bytes; first header word 0. It contains UTF-16LE Settings, Music, Language and English.
- Section 2 at 0x5d50 is 25,232 bytes; first header word 1. It contains Japanese settings/language text.
- The 11 non-common sections each report 826 in their second header word. This is consistent with shared language resources; exact DWR record semantics still require code analysis.
- Loader BMPs additionally include English/Japanese and other locales, but the wording pack and language-page code are the stronger evidence for multilingual UI support.

## Limits and next analysis

English resources exist. It remains unknown whether the Japanese model merely hides selection, always forces a locale, or has model-specific restrictions elsewhere. Presence of the language-page class does not prove that page is reachable on A918.

Next inspect DuiWording loading, the mapping from APCSettingLanguage to DWR resources, and persistent language/destination settings. Prefer selecting existing English resources once the path is understood. Blindly swapping offsets or patching binary constants is not yet justified.

No device connection, firmware write, or execution of extracted ARM code occurred.
