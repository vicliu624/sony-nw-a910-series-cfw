# A918 原厂 FM 页面创建与调用路径（2026-10-18）

本轮仅分析原版 1.03 主程序，没有构建固件、改写设备或修改系统配置。
输入 SHA-256：`a5c94ce492fb7ec9cd7a740d30cb79a1c2b43ee782e2da036a72f57dabdcd177`。
以下地址均为 ELF 虚拟地址，不是文件偏移。

## 已确认的创建链

```text
页面初始化代码 0xF6B8
  → 0x157120：分配 0x11DC 字节，创建 FM 页面对象
      → 0x15574C：构造 DuiPageSID104_S_PLAYFM_MANUAL
         参数：页面编号 104、上级编号 11（Home）、第三参数 0
      → 0x84A18：初始化/检查；非零结果进入销毁路径
  → 0xF6E8：r1 = 104，r2 = 创建结果
  → 0xF6EC 调用 0x87318：将对象登记到页面管理器
```

这段代码实际创建并注册对象，不只是残留类名。创建到注册的这段直线代码没有
FM 能力位判断；但上层启动路径未完全穷尽，不能推断每种启动状态一定执行到这里。

| 地址 | 已确认的操作 |
| --- | --- |
| 0x87318 | 在 `manager + 0x34 + pageId*4` 存放对象指针；检查编号上界和非空参数 |
| 0x86EC4 | 按同一位置返回对象指针 |
| 0x87400 | 判断对应对象指针是否非空 |
| 0x87388 | 清空槽位并返回原先是否有对象 |

清理代码 0x17424–0x1747C 对编号 104 执行存在检查、获取对象、
0x157194 类型转换及销毁、清除注册。这补齐了对象生命周期证据。

## 页面进入处理

FM 类虚表位于 0x47F978；其中 0x156EB4 按行为识别为进入页面处理：

1. 清零内部状态；按参数类型读取可选参数，类型不符返回 1。
2. 用文字编号 21 设置标题；原版为日文「FMラジオ」、英文「FM Radio」。
3. 读取公共系统状态，通过跳转表设置控件状态。
4. 调用 0x1566F4、0x1564EC、0x156CB8 更新页面内容。
5. 通过公共对象虚方法取得组件并继续调用；正常路径返回 4。

页面并非只有标题的空壳。但返回值 4 的框架语义、组件准备顺序和 RF 命令链
尚未全部解出，不能据此宣称已可安全进入或收音。

0x154FE8、0x155050 等方法调用 0x81C10/0x81C40；后两者分别比较系统状态值
8 和 7，不是已经证实的 FM 硬件能力位检查。

## 路由存在，用户入口尚未闭合

Home 分发函数 0x2A028 接受条目类型和目标页面号。类型 3 的跳转表目标为通用
分支 0x2A0B4；目标页非零时，在 0x2A0E0 调用 0x84AEC 发起跳转。
这提供了复用原厂路由的静态依据，不代表现在把参数强改成 104 就能正常使用。
0x84AEC 涉及页面转换状态，不能当作任意时刻可调用的显示函数。

A910 专用 Home 表 0x4634F8 的九条记录均没有目标页面 104，数量固定九项。
此前离线回放也验证 FM 位 0/1 不改变九项的构造数量。
**尚未找到仅改变 FM 开关就自动增加菜单项的机制。**

ICX1101 专用 Home 选项列表固定五项，计数函数 0x23F8C/0x23F94 均返回 5。
资料表 0x462814 中可解码的文字编号为：25 正在播放画面、509 录音画面、
676 电视画面、111 音乐播放画面。首条的首字段为地址 0x5407BC，其运行时内容
尚未解出，不擅自命名。

处理函数 0x23E7C 对选项 151/153 调用 0x85514；135 走传入目标页，表内目标
164；其他交给基类。0x85514 读取当前系统模式后转交 0x84E28；后者按模式分流。
所以“正在播放”是状态相关路由，不能只看表内无 104 就断言没有任何间接 FM
路径；但也没有证据证明它能从正常音乐状态首次启动 FM。

本轮尚未找到用户可执行、已闭合的原厂 FM 进入路径；间接调用未全部穷尽。

## 判断与下一步

- 原厂已有 FM 工厂、注册槽、页面进入处理和销毁路径，可优先研究复用。
- 仍缺 A910 正常界面到 FM 的可达入口、正确状态转换和组件准备条件。
- “恢复现成入口”待证明；“开一个位就自动增加图标”目前没有证据支持。
- 下一重点：解析 0x84E28 模式映射及虚调用目标，查清 FM 模式首次如何建立，
  区分“回到已有 FM 会话”和“启动 FM”；追踪 FM 组件初始化与能力位的关系。
