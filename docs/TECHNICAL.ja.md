# Sony NW カスタムファームウェア技術ガイド

[English](TECHNICAL.md) · [简体中文](TECHNICAL.zh-CN.md) · [日本語](TECHNICAL.ja.md)

## 1. 目的と検証範囲

主目的は日本向けA910シリーズの中国語（簡体字）・英語ローカライズです。ちいかわのテーマはリソース置換、自作プログラムとゲームは独自コード実行の例です。特定テーマやアプリ基盤の提供をプロジェクトの目的とはしていません。Sony NWシリーズの研究に向けた一つの出発点です。

研究手順は他のNWにも応用できる可能性がありますが、形式、鍵、CPU／命令セット、OS、リソース、パーティション、更新手順は機種ごとに調べます。すべてのNWがLinuxや同じUPGを使うとは限らず、A910のアドレス・パッチ・ioctlを流用できるという意味ではありません。

純正更新器にはA916／A918／A919が記載されていますが、実機テストの記録はA918のみです。初期のローカライズ・テーマと一部ゲーム版には動作報告があります。R12は更新に失敗しました。現在の外部プログラム候補および新しい中英ビルドはオフライン検証対象で、過去の成功がそのまま実機認定にはなりません。

現行ソースと本書を最初に読みます。`docs/archive/`は調査当時の記録で、後に否定された仮説もあります。`archive/`の旧ツールや私有入力はGit対象外で、クリーンビルドには不要です。以下はプロジェクト直下のLinux／WSLで普通のファイルを処理する手順です。抽出した更新スクリプトや実機のマウントスクリプトをホストで実行しないでください。

## 3. 純正入力とRockboxの役割

純正URL：`https://walkman.update.sony.net/fw/pc/A910/NW-A910_V1_03.exe`。

| 入力 | バイト数 | SHA-256 |
| --- | ---: | --- |
| Sony EXE | 13,628,920 | `6f745a8ff3c90b7abcd5ea185e6f51e4598492f6de5bdb3256599c6f43e39701` |
| NW_A91X.UPG | 13,734,432 | `cfbcc372e2a18f11c12a080c9e5f039333e09175f5db03ac841a4227d3896b32` |

元EXEはWindowsで有効なSONY Corporationの署名が確認されていますが、変更後UPGの正当性を保証する署名ではありません。ビルダーはハッシュを確認し、EXEを起動せず7zで展開します。更新器、DLL×2、INI、UPG、ライセンス×10の計15ファイルを検査します。キャッシュは`firmware/original/`、展開先は`work/ci/updater/`です。

RockboxはSony UPGの解析、展開、再構築、鍵探索を既に実装していました。本工程はその成果を利用し、想定された16進文字の鍵空間から候補を探して、ヘッダー・4成分の境界・MD5で検証しました。AIが公開鍵暗号を破ったのではありません。既知の古い機種の鍵はこのパッケージには適合しませんでした。

DES等価鍵はASCII **8バイト**の`b8442c44`です。16進数として4バイトに変換しません。ASCIIマーカーは`5dfeff3c`、Rockbox由来KASは`ba49adfd57caba10b771b9bef805b2f9`です。DESのパリティビットにより、表記が違う等価鍵が存在します。

4成分を無変更で再構築したUPGは純正とSHA-256が完全一致し、Rockboxの独立再構築でも一致しました。現在も最終成果物をRockboxで展開して4成分を比較します。これはコンテナー処理の証明であり、安全な書き込みの証明ではありません。保存されたRockboxツールの元コミットは未記録なので、コミットを推測して記載しないでください。

## 4. UPGの構造

整数はリトルエンディアン、DES-ECBは8バイト単位です。

| ファイル位置／復号ヘッダー位置 | 内容 |
| --- | --- |
| 0..15 | 16..EOFに対する生のMD5ダイジェスト |
| 16..63 | 暗号化された48バイトヘッダー |
| ヘッダー+0 | ASCII 8バイト `5dfeff3c` |
| +8、+12 | u32 成分数4、u32予約0 |
| +16+8*i | u32絶対オフセット、u32パディング前サイズ |
| 成分開始位置 | DES暗号文、長さは8の倍数に切り上げ |

オフセットはUPG先頭基準です。MD5、マーカー、整列、順序、非重複、範囲を検査します。マーカーもMD5も発行者認証用の公開鍵署名ではありません。

| 成分 | 純正オフセット | 純正サイズ | 確認された用途 |
| ---: | ---: | ---: | --- |
| 0 | 64 | 1,578 | 実機更新シェルスクリプト |
| 1 | 1,648 | 2,523,136 | Linuxカーネル、syscall解読の再生に使用 |
| 2 | 2,524,784 | 786,432 | ext2 initrd |
| 3 | 3,311,216 | 10,423,215 | gzip圧縮tar rootfs |

初期資料では成分1が不明とされていても、後の解析で用途を確認しています。現在は成分3だけを変更し、最初の3つの暗号化成分を保存、ヘッダー内の長さを更新、MD5を再計算します。`upg.py`はこのA910形式専用です。

```sh
python scripts/inspect_firmware.py --upg work/ci/updater/NW_A91X.UPG --output work/inspect-original
```

ビルドで純正入力を準備してから、新しいwork配下の出力先を指定します。4成分、主要な固定パスのファイル、12個のDWR、inspection.jsonを出力します。任意のtarパスをホストへ展開せず、ARMコードも実行しません。成分0は読むだけです。

## 5. rootfsと一命令の言語パッチ

元tarは613項目。UI本体は`/usr/local/bin/gemini-ICX1101`、ARM Linux ELF、5,691,632バイトです。文字は`/usr/local/share/gemini/res/wording_res/ICX-COMMON_wording.dpk`、画像は同階層の`dui_tex/`です。フォントには`dui_font.dpk`、`ICX1101_dui_font.dpk`があります。英語メニューでも日本語・中国語の曲名には字形が必要です。

文字読み出しは、言語リソースをロード→設定言語IDを読む→DWRを選ぶ→文字IDを引く、という流れです。この純正ELFに限るパッチ位置は次の通りです。

| 項目 | 値 |
| --- | --- |
| 仮想アドレス | `0x96294` |
| ファイルオフセット | `0x8e294` |
| 元命令 | `ldr r3, [r0, #0x14]`、`14 30 90 e5` |
| 英語 | `mov r3, #0`、`00 30 a0 e3` |
| 簡体字 | `mov r3, #6`、`06 30 a0 e3` |

4バイト命令のみ置換し、後続の処理は残します。言語設定ページの追加、地域／NVPの書き換え、別の起動・更新画面の翻訳ではありません。別ELFではPT_LOADを調べ、ファイル内オフセット=`p_offset+VA-p_vaddr`を計算し、ファイルで裏付けられた範囲と元命令を確認します。他版へこの値を盲目的に適用しません。

## 6. 11言語のリソース

DPKは共通セクション1個と11言語です。**DPKセクション番号は言語ID+1**で、0は共通です。

| 言語ID | DPKセクション | 言語 |
| ---: | ---: | --- |
| 0 | 1 | 英語 |
| 1 | 2 | 日本語 |
| 2 | 3 | フランス語 |
| 3 | 4 | ドイツ語 |
| 4 | 5 | イタリア語 |
| 5 | 6 | スペイン語 |
| 6 | 7 | 中国語・簡体字 |
| 7 | 8 | 中国語・繁体字 |
| 8 | 9 | ロシア語 |
| 9 | 10 | 韓国語 |
| 10 | 11 | ポルトガル語 |

各言語826レコード、共通は34レコード。確認した読み取り処理では共通ID 826..859は言語選択を通りません。日本語は648件に文字があり178件は空／予約。元英語360件、対日本語欠落288件。元簡体字359件、欠落289件です。他言語の欠落数は個別集計が必要です。

他言語の開発では、日本語と同じIDで比較、既存訳を保存、欠落だけ補完、フォント／レイアウトを確認し、選択命令を適合させます。リソースが存在しても、訳の完全性、字形、画面への到達性、実機動作は未証明です。11言語すべてが完成した言語パックとは説明しません。これだけで当時のソニーの開発分岐も推断できません。

現行CLIはenとzh-CNのみです。他言語にはTSV列、言語／セクション対応、適切な折返し、測定した欠落数、選択ID、最終成果物のテストを追加します。wrap_textの英語以外の分岐はCJK向けなので、フランス語・ドイツ語の単語折返しにそのまま使いません。既存中英の回帰も維持します。

## 7. DPK／DWRと翻訳再構築

文字DPKヘッダー`<4I`はペイロード長、セクション数、予約0×2。各索引`<QQ`はkeyとオフセット。セクションを変更したら後続オフセットと全体長を再計算し、keyと無関係セクションを保存します。

DWRヘッダー`<4I`はlocale、件数、行長プールのバイトオフセット、UTF-16プールのバイトオフセット。レコード`<bbHHH`は8バイトで、符号付き行数、secondary、u16行長索引、u16文字索引、u16メタデータです。索引単位はバイトではなく16ビット値。行長にはUTF-16 NULが含まれます。範囲と終端を検査し、動的内容の挿入に使うsecondaryや空行も残します。

`parse_dwr()`で解析し、`fill_dwr()`は日本語に文字があり対象訳だけ空のレコードを補完します。対象メタデータを維持し、欠落項目のsecondaryは日本語に合わせ、新しい長さと文字をプール末尾へ追加します。16バイト整列、text_pool再計算、u16索引上限65535を守ります。長い訳を元の位置に上書きすると後続データが壊れます。

`translations/missing.tsv`はid／english／simplified_chinese列、文字列の\nは改行です。追加訳は約20表示幅単位（ASCII=1、全角=2）、行数は日本語以下。これは目安で、ピクセル単位の表示保証ではありません。

```sh
python scripts/wording.py --upg work/ci/updater/NW_A91X.UPG --language en --output work/localization/en.dpk
python scripts/wording.py --upg work/ci/updater/NW_A91X.UPG --language zh-CN --output work/localization/zh-CN.dpk
```

CIは選択言語をTSVから生成し、288／289件の補完、対日本語の欠落ゼロ、元レコード保存を確認して命令を0／6にします。実験ランチャー独自の表示は現状英語です。

## 8. アイコン・アニメーション・背景

画像DPKも16バイトヘッダーを持ち、索引は`<4I`でkey／category／offset／reservedとして読めます。入れ子もあり、サイズ・件数・整列したオフセットで判別します。確認した名前ハッシュは0から各バイトについて`h=(37*h+byte)&0xffffffff`、最後に`h|0x80000000`です。category、予約値、入れ子を保存します。

変更例のDTXはformat 5。先頭`<HHI`が幅・高さ・形式、ヘッダー全体16バイト、続いてリトルエンディアンRGB565です。サイズは`16+2*width*height`、画素は`((R>>3)<<11)|((G>>2)<<5)|(B>>3)`。これは観察した形式5に限り、他形式へ一般化しません。

ホームの語幹はi_shuf／oneseg／search／photo／music／video／setup／rec／now。`home_<stem>.dtx`、`_hot.dtx`、番号付きフレームがあります。単純な通常／選択の2枚だけではなく、静止・選択・遷移の全参照を調べます。プレビュー画像だけでは実際の状態遷移を証明できません。

確認した画面は240×320。ヘッダーy=0..27、80×72の9タイルy=28..243、機能名背景240×44がy=244..287、状態背景240×32がy=288..319。一部DTXは高さ70なので個別ヘッダーを守ります。機能名背景はICX1101_home_anim.dpkの葉key 0xe60ccd8f、親0xaa48c2d0、テクスチャスロット21です。状態背景は他ページと共用です。

最初の背景の下側が純正のままだった原因は、グリッドと下の背景が別リソースだったためです。同じキャンバスをy=28／244／288／320で分割し、白い文字の読みやすさと共用ページを確認します。他の240×320画像は終了／起動画面かもしれず、ホーム壁紙とは限りません。最初は同じサイズでDTXヘッダーとDPK索引を保ちます。ちいかわはこの処理の一例にすぎません。

## 9. ソース差分の更新

5差分はGemini、文字、2画像パック、`/etc/init.d/gemini`です。manifestは元・結果・差分のSHA-256と結果長を保持します。zlib展開した差分をゼロ埋め元データとXORし、結果長で切ります。CIはこの入力を使い、絵を編集可能な原稿から描き直してはいません。

```sh
python scripts/update_resource_patch.py --original-upg work/ci/updater/NW_A91X.UPG --path ./usr/local/share/gemini/res/dui_tex/dui_tex.dpk --replacement work/my-theme/dui_tex.dpk
# プレビューを確認し、--apply付きで差分とmanifestを更新。
```

既存の許可された1ファイルだけを更新し、実機やUPGは書きません。画像の意味的な正しさは別検査です。葉の変更・寸法・ヘッダーを比較し、最終UPGの独立展開と容量チェックを行います。別ファイル・別機種には検証側も明示的に拡張し、ハッシュ検査を削って通さないでください。

言語命令と文字は基線差分の後で再生成します。これらの差分だけを書き換えてもcomplete_packと選択処理を上書きできません。翻訳はTSV／wording、選択はビルダーを変更します。純正テーマ／入口なしプロファイルは将来実装できる機能で、現在のCLIフラグではありません。

## 10. 自作コードの実験経路

rootfsの起動スクリプトからSony起動前にa918-boot-dispatchを呼び、A918_BOOT_BYPASSで再帰を防ぎます。元の緊急・Sony経路を保ちます。ホーム9項目とOPTIONにはフックしません。R6／R7のホームフック実験はフリーズを起こして廃止したため、再利用しません。

`nvpflag -x fup`が明示的に`0x00000000`のときだけ選択画面へ進みます。不明／更新中／USB接続／状態読み取り失敗ならSonyへ渡します。読むことはNVP書き込みの許可ではありません。既定WALKMANはデータをマウントしません。APPS選択後、既存マウントと/tmpのramfs/tmpfsを確認し、`/dev/mtdblock/2`を`/tmp/a918-game-disk`へrw,nosuid,nodev,noexecで私有マウント、USBを再確認します。

APPS/<id>/app.iniを読み、長さ・CRCと基本ELFを検査してRAMの`/tmp/a918-app-runtime/program`へコピーします。cwdはアプリ自身のフォルダー。プロセスグループの心拍で通常の停止を監視します。Sonyへ戻す前のアンマウントが3回失敗するとexit 91でSonyを起動せず二重アクセスを防ぎます。シェルのタイムアウトは中断不能なカーネルI/Oを救えません。サンドボックスはありません。[APPS](APPS.md)を参照してください。

ROM／プログラム／セーブをユーザー領域に置き、システム容量増加と再書き込みを避けます。iDは4MiB ROMをRAMに読み、CRC検査後、変更をstateに保存しrom.binを上書きしません。保存は一時ファイル→fsync→rename→ディレクトリfsync。最後の失敗は置換後に起こり得ます。毎保存のバックアップではなく、FATの停電耐性も未検証です。

## 11. CPU・syscall ABI・表示・入力

`-march=armv5te -marm -mfloat-abi=soft`、static／freestanding、`_start`を使い、現代のglibcに依存しません。SonyのARM Linux 2.6.10ではARMモードの`svc 0`＋r7方式は想定どおり動きません。`SWI 0x900000+nr`の即値を使います。

sony_oabi.SはC呼び出しのAAPCS規則を保ちながら288個のSWIスタブで発行します。C構造全体を古いOABIに変更した意味ではありません。シグナル復帰も正しい即値が必要です。QEMU-userだけの成功ではこの問題を発見できませんでした。

check-apps-kernel-abi.pyはUnicornで元カーネルのvector_swi=0xc0022ae0、sys_call_table=0xc0022ba4、arm_syscall=0xc0028388を再生します。無関係なCP15設定を飛ばして選択先で停止し、実機syscallは実行せず28番号を確認します。

boot_arm.cは`/dev/fb/0`、`/dev/input/event0`、`/dev/usbconn`を開きます。QFB ioctl 0x80044e04、{0,33}は表示タイミングを変更するため、方向ビットだけで読み取り専用とは呼べません。0x80000バイトをマップし、0x40044e01、{1,0x800,255,page,0,0}でRGB565を表示。USBは0x80046701で、失敗時はSonyへ。EVIOCGRABは0x40044590。原キーコード0=中央、1=右、2=左、3=上、4=下です。押下・解放を処理し、引き渡し時に独占、マッピング、FDを解放します。別機種への流用値ではありません。

ARMでも古いARMv5とCortex-M3のThumb-2生成コードは同一ではありません。iDは本機ではインタープリターを使います。MHzだけでホストを選択しません。

## 12. R12失敗とインストール容量

元の更新スクリプトは`mkfs.ext2 -b 4096 /dev/mtdblock/1`を先に行い、マウント後に成分3をfwpupからtarへ渡します。**フォーマットが先で、A/Bロールバックはありません。** スクリプト・カーネル・initrdを保存しても危険自体は残り、PC更新器の画面変更では解決しません。

純正NANDドライバーのroot既定値は0x03000000=48MiBで、実機形状の読み戻しではありません。Sony BusyBox mke2fs 1.37で12288ブロック、ファイル割当前11895空き。R11は11704ブロック必要、R12は11921必要で、最低26ブロック=106496バイト超過しました。容量失敗を再現し症状と合いますが、実機ログがなく唯一原因と断定しません。R12は禁止です。

現行ゲートはwork内の普通のイメージだけを作り、元mke2fsをQEMUで実行、debugfsでゼロを含む全データ・間接ブロック、ディレクトリ、リンクを割り当て、4MiB以上の余裕を要求します。物理ディスクはマウントしません。gzipサイズ、ファイル長合計、スパース保存、現代mkfsの既定値では代用しません。

同モデルの純正空き5,312,512バイト、R14英語5,267,456バイト、割当増加45,056バイト=44KiB。新しい言語別候補は各capacity.jsonを確認します。実機dfや不良ブロックの測定ではありません。外部保存はシステム容量増加を解決しますが、電源・書込失敗・復旧手段は別問題です。

## 13. 検証とリリース

純正EXE検証→正確な展開→コンパイル→ARMテスト→模擬ディスパッチ→カーネル再生→5差分→選択言語生成→tarとメタデータ比較→容量割当→UPG→Rockbox独立展開→ZIPとSHA-256の順です。追加ファイル2個でrootfsは615項目。元項目の順、所有者、権限、時刻、リンク等を維持し、検査後に成果物を出力します。

公開テストはコンテナー3件、既存訳保存・境界の回帰5件、ROMなしARM17件、模擬ディスパッチ14件、カーネル解読28件とビルド時自検査です。実ROMの起動・保存・初期化には私有入力が必要で、公開CIでは明示的に除外します。実機USB、停電、休止、NAND/FAT、音質の証明ではありません。音声ドライバーを残すことは変更範囲を狭めるだけで音質測定ではありません。

環境・手順は[BUILD](BUILD.md)。VERSIONは工程SemVer、Sony側は1.03。CIはen／zh-CNを別々に生成し、両方成功後に一致タグで実験版のプレリリースを作ります。自動書き込み・NVP変更はしません。実行記録は [GitHub Actions](https://github.com/vicliu624/sony-nw-a910-series-cfw/actions) にあります。ローカルとCIの結果は区別して記録します。

## 14. 復旧の限界と廃棄した仮説

故障A918はR12更新を繰り返し、USBの認識時間はないと確認されています。強制USBキーや同故障の確実な復旧手順は未確認です。通常rootfsの緊急USB処理はrootfsが使えないと動く保証がありません。コメント内の再生キー復旧例は無効、UIの工場キー解析も更新画面で使える証拠ではありません。UART端子、電圧、利用できるshellも未確定です。推測の短絡、他機種のキー、盲目的なRESET、通信・バックアップなしのフラグ編集を案内しません。

R11、純正、失敗の証拠を保存します。[R12調査](archive/r12-recovery-investigation.md)、[公開復旧証拠](archive/recovery-public-evidence-2026-10-19.md)、[容量比較](archive/rootfs-usage-original-vs-r14.md)を参照してください。古い未検証表示と後の成功報告は時系列で区別します。

## 15. 別言語・別機種への手順

1. 型番、基板、版、ハッシュを固定し、事実・推論・未知を区別する。
2. オフライン展開と無変更の完全往復を成立させる。A910の鍵を前提にしない。
3. 実機側インストーラーからパーティション、書込順、容量、更新フラグ、復旧条件を調べる。
4. 対象CPU／OS／ABI、文字・字形・言語対応を確認し、アドレスやioctlを移植しない。
5. 小さな資源／言語変更から始め、許可変更一覧、既存訳とメタデータを維持する。
6. 最終パッケージを独立展開、全容量と余裕を検査し、正確な復元用ファームウェアと未実施テストを残す。
7. 正常に動く機器と明確な復旧条件で実機検証する。オフライン成功を全機種の安全性に一般化しない。

README→本書→BUILD→関連ソースの順に読みます。既知のUPG鍵、DWR、OABIを最初から再解析する必要はありません。他言語の欠落と字形は個別調査し、新事実には入力ハッシュ・命令・出力・対象範囲・限界を添えます。コンパイル成功を完成宣言に置き換えないでください。
